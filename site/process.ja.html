投稿から掲載まで（日本語訳）

最終更新：2026-11-12。

これは英語の From submission to listing の訳です。訳と英語の文が食い違うときは、英語の文が適用されます。

この頁は、一つの投稿を始めから終わりまでたどります。決まりそのものは、投稿の規程とモデレーションの規程にあります。この頁と食い違うところは、規程が適用されます。

始める前に

要るものは四つです。投稿に要るほかのことは、確かめることの頁にまとめてあります。

  1. Zenodo、Figshare、OSF Preprints、SocArXiv、MetaArXiv、arXiv、Preprints.org、SSRN、Research Square、SciELO Preprints、Qeios、ScienceOpen Preprints、Advance、KC Works、Jxiv のどれかに、DOI 付きで預けたプレプリント。投稿の規程が定めるとおり、2026-11-23 から、作品の最初の DOI が登録されてから 6 か月以上たっている必要があります。
  2. 預けたものに付けた CC BY 4.0、CC BY-SA 4.0、CC0 1.0 のどれか。DOI のメタデータに出ている必要があります。
  3. ORCID iD。登録は無料です。
  4. GitHub のアカウント。登録は無料です。

作品の著者全員が、掲載に同意している必要があります。投稿の規程が定めるとおり、2026-11-23 から、初めての投稿には研究者一人の紹介も要ります。紹介する研究者は、学術誌の論文・本の章・本を持つ人です。言語モデルやその他の生成モデルを使った場合は、使った道具と、何に使ったかを書きます。2026-11-24 から、様式は研究資金、利益相反、人を対象とする研究と研究倫理についての申告も求めます。任意で、データとコードの所在も尋ねます。

手順 1. GitHub のユーザー名を確かめる

投稿は GitHub の issue です。Sophaxis のリポジトリに公開で置く投稿で、その下にコメントが付きます。GitHub のアカウントが無い場合は、github.com/signup で作れます。

ユーザー名は、GitHub のプロフィールのアドレス https://github.com/<your username> の最後の部分です。サインインしたあとは、右上の自分の画像の下のメニューにも出ます。

手順 2. ORCID の記録を GitHub にリンクする

  1. orcid.org でサインインすると、ORCID の記録が開きます。ORCID iD は、名前の下にある 16 桁の番号です。
  2. 「Websites & social links」の節を探し、その編集のボタン（鉛筆）を押します。
  3. 「Add link」を選びます。GitHub のような題と、アドレス https://github.com/<your username> を書きます。
  4. 公開の範囲を「Everyone」にして、保存します。

Sophaxis は、こうして、投稿を開いた人が作品の著者であることを確かめます。Sophaxis が ORCID の記録から読むのは、名前・リンク・業績だけです。ORCID にメールアドレスや国を問い合わせることはありません。

手順 3. 投稿の issue を開く

  1. 投稿の様式を開きます。GitHub がサインインを求めたら、サインインします。そのあと様式が開きます。同じ様式の日本語版もあります。
  2. 題の「[Submission]」のあとに、作品の題のような短い言葉を足します。
  3. DOI、ORCID iD、分野（合えば下位の分野も）、生成モデルについての申告と、2026-11-24 からは研究資金・利益相反・研究倫理についての申告を書き、確認の欄に印を付けます。平易な要約と二つ目の言語の要旨は任意です。
  4. 様式のいちばん下のボタンを押して、issue を作ります。

題・著者・要旨・ライセンスは、DOI のメタデータから取ります。手で打ち込むことはありません。

issue は公開されます。GitHub のユーザー名と、そこに書いたことはすべて、誰でも読めます。自分が開いた issue に新しいコメントが付くと、GitHub が知らせます。知らせは github.com に出て、初期の設定ではメールでも届きます。

手順 4. 自動の確認が答える

ふつうは数分のうちに、「Automatic checks」という題のコメントが issue に付きます。コメントは、預け先、ライセンス、DOI のメタデータ、ORCID の記録からのリンク、著者であることを、それぞれ通ったか通らなかったかで示します。issue には verified か unverified のラベルが付きます。

確認が通らなかった場合は、コメントがその理由を書きます。ORCID の記録のリンクのような原因を直してから、issue を編集します。すると、確認がもう一度走ります。issue を編集するには、最初の投稿の右上のメニュー（⋯）を開き、「Edit」を選び、要るところを変えて保存します。何も変えない編集では、確認は走りません。

預け先が Sophaxis に PDF の取得を許さない場合は、預けた PDF を issue に添付するよう、コメントが求めます。Zenodo、Figshare、arXiv、Research Square 以外のすべての預け先がこれに当たります。添付は任意で、ファイルは 20 MB までです。添付するには、ファイルを issue のいちばん下のコメントの欄に引き入れ、そのリンクが出るのを待ってから、コメントを投稿します。

投稿が確かめられた場合、コメントは、預け先にある DOI のメタデータについての助言を添えることもあります。たとえば、要旨、ライセンス、キーワードが欠けていることです。助言は deposit-check から来ます。掲載を決めるものではありません。検索エンジンや索引は、PDF ではなくこのメタデータを読みます。多くの預け先では、新しい版を作らずにそれを直せます。

確認を通っても、受理ではありません。

GitHub と ORCID のボタンの名は、変わることがあります。手順は変わりません。

手順 5. モデレーターが投稿を読む

モデレーターは、確かめられた投稿を、モデレーションの規程に照らして読みます。見るのは、対象の分野、学術論文の形、生成モデルについての申告、そしてスパム・嫌がらせ・第三者の個人データが無いことです。モデレーションは査読ではありません。証明・論証・データは確かめません。

目安として、判断は投稿の当日に出ることもありますが、数週間から数か月かかることもあります。判断は issue に書きます。

手順 6. 判断

受理した場合は、2026.0001 のような Sophaxis の番号を付けて記録の頁を公開し、issue を閉じます。預け先が許す場合は、そのあとで、手を加えていない PDF の写しを加えます。

断る場合は、モデレーターが issue に短い理由を書きます。投稿者は、そこで答えることができます。その後、運営者が投稿をもう一度見直し、その判断が最終のものになります。

掲載のあと

  • 新しい版：預け先に預けてから、既存の Sophaxis の番号を書いて投稿の issue を開きます。
  • 記録の誤り：記録の頁にある「Report an error in this record」を使います。
  • 撤回：著者なら誰でも一人で、撤回の規程に沿って作品を撤回できます。
  • 出版：後の版が学術誌、会議録、書籍で出版されたときは、著者なら誰でも一人で、出版された版の様式で報告します。プレプリントは載ったままです。

ほかの問いへの短い答えは、よくある質問にあります。
